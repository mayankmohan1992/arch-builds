# Managed set: rebuilt with -march=znver4 by GitHub Actions.
# Only packages ALHP does not cover, that fit a 14 GB / 6 h runner, and that are
# safe to replace. One entry per PKGBUILD (split packages are built together).
#
# Spec format (see scripts/lib.sh):
#   git              Arch official packaging, fetched from gitlab.archlinux.org
#   aur:name         AUR recipe, git-cloned at build time
#   omarchy:name     omacom/omarchy-pkgs recipe, sparse-checked out at build time
#   local:name       hand-written recipe in pkgs/name (bumped by hand)
#
# Recipes are fetched fresh on every build, so a version bump upstream always
# brings its PKGBUILD with it. That is what makes "rebuild only when upstream
# actually moved" true without anybody editing a recipe.

# --- Vendored recipes (pkgs/<name>) -----------------------------------------
# Hand-maintained because upstream has no usable recipe of its own. These are
# NOT auto-tracked: bump pkgver deliberately, patches may need refreshing.
#
# xmrig-cuda-tuned: AUR xmrig does not ship the CUDA backend, and the CPU must
# be znver4 for RandomX. Replaces stock xmrig via provides/conflicts.
local:xmrig-cuda-tuned
# gupax: AUR is stuck at 1.3.10 while upstream is 2.0.2, and the recipe carries
# a local patch. Its build-time tools do not need nightly (we dropped
# -Zlocation-detail=none so stable cargo works in CI).
local:gupax
# t3code: only -bin exists in the AUR (it repackages the released AppImage).
# This recipe builds from the source tag instead, so the bundled Rust helper is
# compiled for znver4. pkgs/t3code/TRACK makes it follow upstream releases
# automatically: the latest GitHub tag becomes the pkgver at build time.
local:t3code
# omafeed: the Rust RSS reader Omarchy ships. Its own recipe stops at
# `cargo build --release` (thin LTO over 16 codegen units); this one adds fat
# LTO + one codegen unit and PGO trained on the real CLI, on top of
# RUSTFLAGS=-C target-cpu=znver4. TRACK follows pch/omafeed releases, so a new
# version is rebuilt without touching anything. Installs no autostart entry or
# service: the app only runs when launched by hand.
local:omafeed

# --- Coverage gaps: no v4 repo ships these any more --------------------------
# ALHP's core/extra-x86-64-v4 no longer carry these three, so the only v4 build
# that ever existed is the one installed from ALHP's older set (pkgrel .1).
# With no repo offering it, pacman prints "local (x-1.1) is newer than extra
# (x-1)" on every upgrade and never refreshes the package. Publishing them here
# at the same <pkgver>-<pkgrel>.1 keeps the v4 build and ends the warning. All
# three are cheap builds that never execute their own output, so they are safe
# on a Zen 3 runner.
fakeroot
docker-buildx
limine

# --- Deliberately excluded ---------------------------------------------------
# System-breaking: glibc, gcc/gcc-libs, binutils, base, filesystem,
#   linux-firmware/*, keyrings, pacman-mirrorlist, the kernel. ALHP excludes
#   them too; -O3/LTO there risks the whole system for ~1-3%.
# Deep system libs (glib2, curl, sqlite, zlib, nettle, libseccomp...): same
#   reason, and they are rebuilt constantly by Arch.
# Chromium-scale, exceeds 14 GB disk or 6 h job: chromium, webkit2gtk-4.1,
#   qt6-webengine, opencv, js140, rust, deno.
# Proprietary/prebuilt: nvidia-utils, opencl-nvidia, nvidia-open-dkms, cuda,
#   electron43, electron44.
# No compiled code worth rebuilding: fonts, icon themes, data packages,
#   pure-Python/JS packages, shell scripts (yt-dlp, udiskie, ufw, npm, ...).
# Go binaries that ignore CFLAGS: yay, tldr is kept only because the recipe
#   still builds it; its gain is nil.
# python: Arch already builds it PGO+LTO; gain is ~3% on an interpreter the hot
#   apps do not use, and its PGO profile step needs a generated locale.
#
# aether (omarchy): its recipe installs a PREBUILT Go binary from GitHub
#   releases, so rebuilding it changes nothing. Optimising it needs a wails +
#   node + webkit2gtk source build, which is heavy and fragile for an app that
#   runs only while you are changing themes. Revisit if it becomes hot.
#
# omarchy-hyprland-titlebars (omarchy): a Hyprland plugin is only loadable by
#   the exact Hyprland build it was compiled against, and the recipe pins
#   hyprland=0.57.0 while this machine runs 0.56.2 (IgnorePkg=hyprland).
#   Rebuilding it against ALHP's Hyprland would risk the compositor for a
#   marginal gain. Left to Omarchy.
#
# libasyncns: dropped. Upstream's git host (git.0pointer.net) serves a cert
# that fails hostname validation, so the source cannot be fetched reliably.
# It is a tiny, effectively deprecated library with no meaningful gain.
#
# kirigami: dropped. KDE re-uploaded the 6.31.0 tarball after Arch packaged it
# (actual sha256 811a8a15... vs Arch's f21df727...), so the recipe fails its
# own checksum. Not worth trusting a re-tagged upstream artifact.
# ruby: dropped. Its build executes the freshly compiled miniruby, and GitHub's
# standard runners are AMD EPYC (Zen 3, no AVX-512), so a znver4 binary SIGILLs
# ("Illegal instruction (core dumped)"). Packages that run their own output
# during the build cannot be v4-built on this infrastructure. The old asset is
# removed from the release so stock ruby takes over on the next Arch bump.
#
# libcloudproviders: dropped, same class as ruby. Its build runs
# gobject-introspection against the freshly compiled v4 library, which SIGILLs
# on GitHub's Zen 3 runners. Any package that executes its own output during
# the build cannot be v4-built here.

# nodejs is deliberately last: its V8 build takes 2-3 hours on a 4-core runner.
# It builds for x86-64-v3, not v4, because its own torque/mksnapshot tools run
# during the build and SIGILL on Zen 3 runners (see ci-build.sh).
nodejs
