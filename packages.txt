# --- Deliberately excluded ---------------------------------------------------
# System-breaking: glibc, gcc/gcc-libs, binutils, base, filesystem,
#   linux-firmware/*, keyrings, pacman-mirrorlist, the kernel. ALHP excludes
#   them too; -O3/LTO there risks the whole system for ~1-3%.
# Deep system libs (glib2, curl, sqlite, zlib, nettle, libseccomp...): same
#   reason, and they are rebuilt constantly by Arch.
# Chromium-scale, exceeds 14 GB disk or 6 h job: chromium, webkit2gtk-4.1,
#   qt6-webengine, opencv, js140, rust, deno.
# Proprietary/prebuilt: nvidia-utils, opencl-nvidia, nvidia-open-dkms, cuda,
#   electron43, electron44.
# No compiled code worth rebuilding: fonts, icon themes, data packages,
#   pure-Python/JS packages, shell scripts (yt-dlp, udiskie, ufw, npm, ...).
# Omarchy-owned: excluded by decision, their channel owns them.
# python: Arch already builds it PGO+LTO; gain is ~3% on an interpreter the hot
#   apps do not use, and its PGO profile step needs a generated locale.

# libasyncns: dropped. Upstream's git host (git.0pointer.net) serves a cert
# that fails hostname validation, so the source cannot be fetched reliably.
# It is a tiny, effectively deprecated library with no meaningful gain.

# kirigami: dropped. KDE re-uploaded the 6.31.0 tarball after Arch packaged it
# (actual sha256 811a8a15... vs Arch's f21df727...), so the recipe fails its
# own checksum. Not worth trusting a re-tagged upstream artifact.
# ruby: dropped. Its build executes the freshly compiled miniruby, and GitHub's
# standard runners are AMD EPYC (Zen 3, no AVX-512), so a znver4 binary SIGILLs
# ("Illegal instruction (core dumped)"). Packages that run their own output
# during the build cannot be v4-built on this infrastructure.
